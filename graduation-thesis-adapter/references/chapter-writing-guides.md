# Chapter Writing Guides

## Abstract

- Summarize project background, system goal, core functions, technical stack, and overall result.
- Do not include unsupported metrics.

## Introduction

- Explain background, significance, research status, and thesis structure.
- Keep claims conservative and aligned with the project type.

## Requirements Analysis

- Describe user roles, workflows, functional requirements, and non-functional requirements.
- Prefer real business flow over generic textbook language.

## Overall Design

- Cover architecture, module division, and database design.
- Keep descriptions tied to actual repository structure and schema.

## Detailed Design And Implementation

- Describe real modules, interfaces, data flow, and implementation logic.
- Expand subsections according to actual project modules when the template allows it.

## Testing

- Prefer functional verification and scenario-based validation.
- Do not write stress-testing or performance tables unless evidence exists.

## Conclusion

- Summarize actual completed work and realistic follow-up improvements.
