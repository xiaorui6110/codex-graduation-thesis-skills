# Project Grounding Rules

## Principle

Use real project evidence as the authority for thesis facts.

## Acceptable Evidence

- source code
- database schema
- configuration files
- API definitions
- project documents
- user-supplied project descriptions
- existing screenshots only when they clearly belong to the real system

## Forbidden Content

- invented innovation points
- invented performance benchmarks
- invented deployment scale
- invented user volume
- invented test conclusions
- invented references

## Writing Rule

If evidence is incomplete, use `[待补充]` instead of guessing.
