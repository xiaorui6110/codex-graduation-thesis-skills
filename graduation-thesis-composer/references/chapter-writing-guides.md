# Chapter Writing Guides

## Abstract

- Summarize project context, system goal, core capabilities, and implementation result.
- Avoid unsupported metrics.

## Introduction

- Cover background, significance, status, and thesis structure.
- Keep conclusions conservative.

## Requirements Analysis

- Describe roles, flows, functional and non-functional requirements.
- Prefer repository-backed business flow language.

## Overall Design

- Focus on architecture, module boundaries, and data design.
- Link descriptions to real code and schema artifacts.

## Detailed Design And Implementation

- Explain actual module behavior, key interfaces, and implementation path.
- Expand subsections only when template allows.

## Testing

- Prefer functional verification and scenario-based validation.
- Do not claim pressure-testing outcomes without evidence.

## Conclusion

- Summarize completed work and realistic future improvements.
